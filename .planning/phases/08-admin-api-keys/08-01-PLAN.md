# Plan 08-01: Admin UI with API Key Management

## Goal
Implement the Admin micro-UI with real API key lifecycle management, connecting to the Core API endpoints.

## Background
The Core API already has API key endpoints (`/v1/api-keys`) implemented with full CRUD operations. The admin-ui currently uses mock data and needs to be connected to the real API.

## Implementation Steps

### 1. Types (`frontend/apps/admin-ui/src/types/index.ts`)
Define TypeScript interfaces matching the API schemas:
- `APIKey` - API key metadata (without the plain key)
- `APIKeyCreate` - Creation request payload
- `APIKeyCreateResponse` - Response with the plain key (shown once)
- `APIKeyListResponse` - Paginated list response

### 2. API Service (`frontend/apps/admin-ui/src/services/apiKeysApi.ts`)
Create API client for BFF endpoints:
- `createApiKey(data: APIKeyCreate)` - POST /api/v1/api-keys
- `listApiKeys(page, pageSize)` - GET /api/v1/api-keys
- `revokeApiKey(id: string)` - DELETE /api/v1/api-keys/{id}

### 3. Pinia Store (`frontend/apps/admin-ui/src/stores/admin.ts`)
State management for admin features:
- State: `apiKeys`, `totalApiKeys`, `isLoading`, `error`, `newlyCreatedKey`
- Actions: `loadApiKeys`, `createApiKey`, `revokeApiKey`

### 4. UI Implementation (`frontend/apps/admin-ui/src/App.vue`)
- Connect stats cards to store
- Implement API Keys table with real data
- Implement Create Key modal with form
- Implement One-time key display
- Implement Revoke confirmation

## Dependencies
- Shared components from shell (via Module Federation)
- bffClient from shell (via Module Federation)

## Success Criteria
1. Admin UI builds successfully
2. Can list API keys from backend
3. Can create new API keys
4. Plain key shown only once after creation
5. Can revoke API keys
6. Proper loading and error states
