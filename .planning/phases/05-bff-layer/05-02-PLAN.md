<objective>
Implement the REST API proxy layer that forwards all frontend requests to the Core API (FastAPI) with proper JWT authentication. Every request from the BFF to the Core API must include an Authorization: Bearer header with the user's access token. Requests without a valid session are rejected with 401 before reaching the Core API.

Purpose: Provide a secure, authenticated gateway between frontend and Core API with transparent token management.
Output: Working proxy that forwards all API calls with proper authentication and logging.
</objective>

  <name>Task 1: Implement Core API proxy with JWT forwarding</name>
  <files>bff/src/proxy/core-api.ts, bff/src/types/api.ts</files>
  <action>
Create the HTTP proxy to the Core API with JWT injection:

1. Create `bff/src/types/api.ts` - Type definitions:
   - CoreAPIConfig interface { baseUrl: string, timeout: number }
   - ProxyOptions interface for request modification
   - APIResponse type for standardized responses
   - Error response types (401, 403, 500)

2. Create `bff/src/proxy/core-api.ts` - Proxy implementation:
   - Use http-proxy-middleware (npm install http-proxy-middleware)
   - Configure proxy to API_URL (default: http://api:8000)
   - Implement onProxyReq handler to:
     * Get access_token from session (req.session.accessToken)
     * Add Authorization: Bearer <token> header
     * Add X-Request-Id header for tracing (generate UUID)
     * Log proxy request (method, path, target)
   - Implement onProxyRes handler to:
     * Log response status and duration
     * Handle 401 from Core API (token expired) → trigger refresh
     * Pass through all other responses unchanged
   - Implement onError handler for connection failures
   - Support path rewriting if needed (/api/v1 → /v1)
   - Timeout configuration (30s default)
   - Handle multipart/form-data for file uploads (ingestion)

3. Token refresh on 401 logic:
   - When Core API returns 401, attempt refresh using refresh_token
   - If refresh succeeds, retry original request with new token
   - If refresh fails, clear session and return 401 to frontend
   - Implement exponential backoff for retries (max 3 attempts)

4. Export createProxyMiddleware() factory function

Security requirements:
- Never log the actual JWT token (redact Authorization header in logs)
- Validate API_URL is configured before starting
- Reject requests if session has no access token

Wire up the proxy routes with session validation:

1. Create `bff/src/middleware/auth-proxy.ts`:
   - attachAuthHeader middleware:
     * Checks req.session.accessToken exists
     * Attaches token to req.headers.authorization
     * Sets X-User-Id header from session
     * Sets X-User-Roles header from session
   - requireValidSession middleware:
     * Calls validateSession (from 05-01)
     * Returns 401 JSON response if no session
     * Error format: {error: "Unauthorized", message: "..."}

2. Create `bff/src/routes/api.ts`:
   - Initialize express.Router()
   - Apply requireValidSession to all routes
   - Mount proxy middleware for all routes:
     * router.use('/', createProxyMiddleware())
   - Handle specific routes if needed (health check passthrough)
   - Add error handler for proxy failures:
     * 502 Bad Gateway if Core API unavailable
     * 504 Gateway Timeout on timeout

3. Update `bff/src/app.ts` (from 05-01):
   - Import and mount apiRouter at /api
   - Ensure session middleware runs BEFORE api routes
   - Add request logging middleware (method, path, status, duration)
   - Add CORS headers for API routes (credentials: true)

4. Route mapping:
   - /api/v1/* → proxies to Core API /v1/*

   - All routes require valid session except /health, /auth/*
