Purpose: Deliver real-time UX for ingestion status and improve API performance with intelligent caching.
Output: Working WebSocket server with ingestion event relay and Redis caching layer for search endpoints.
</objective>

<task type="auto">
  <name>Task 4: Implement Redis caching layer with invalidation</name>
  <files>bff/src/cache/redis-cache.ts, bff/src/cache/middleware.ts</files>
  <action>
Implement response caching for hot API endpoints with automatic invalidation:

1. Create `bff/src/cache/redis-cache.ts`:
   - Use ioredis client for cache operations
   - Implement cache key generation:
     * Format: "cache:{method}:{path}:{hash(query+body+user)}"
     * Include user ID in key for user-specific responses
     * Hash using MD5 or SHA256 of sorted params
   - Implement getCachedResponse(key: string):
     * Get from Redis with TTL check
     * Parse JSON response
     * Return null if miss or expired
     * Log cache hit/miss at debug level
   - Implement setCachedResponse(key, data, ttlSeconds):
     * Serialize to JSON
     * Set with EXPIRE (Redis handles TTL)
     * Default TTL: 300s (5 min) for search, 60s for other
     * Compress large responses if needed
   - Implement invalidateCache(pattern: string):
     * Support wildcards: "cache:GET:/v1/search:*"
     * Use Redis SCAN to find matching keys
     * DEL keys in batches
     * Log invalidation count
   - Implement invalidateByTags(tags: string[]):
     * Maintain tag→key index in Redis (Set per tag)
     * Invalidate all keys associated with tags
     * Tags: 'search', 'domains', 'documents', 'user:{id}'
   - Cache configuration:
     * MAX_CACHE_SIZE (prevent memory issues)
     * Default TTLs by endpoint pattern
     * Cache skip headers (Cache-Control: no-cache)

2. Create `bff/src/cache/middleware.ts`:
   - cacheMiddleware(options: CacheOptions):
     * Check Cache-Control header (skip if no-cache)
     * Generate cache key from req
     * Check cache for existing response
     * On cache hit: return cached response, skip proxy
     * On cache miss: continue to proxy
     * After proxy response: store in cache if cacheable
   - Determine cacheability:
     * Only cache GET requests
     * Skip if 4xx/5xx response
     * Skip if response > MAX_SIZE
     * Skip if Cache-Control: private/no-store
   - Response capture:
     * Intercept proxy response
     * Capture status, headers, body
     * Store in Redis asynchronously (don't block response)
   - Apply middleware selectively:
     * /v1/search - 5 min TTL
     * /v1/domains - 1 min TTL
     * /v1/domains/:id - 1 min TTL
     * Skip /v1/ingest (POST) and auth routes

3. Cache invalidation triggers:
   - On document ingestion complete → invalidate search cache
   - On domain create/update/delete → invalidate domains cache
   - On API request with mutation (POST/PUT/DELETE) → invalidate related caches
   - Use Redis pub/sub for cross-instance invalidation

4. Update `bff/src/routes/api.ts`:
   - Apply cacheMiddleware to specific routes
   - Configure TTL per route pattern
   - Ensure cache runs AFTER auth but BEFORE proxy

5. Monitoring:
   - Cache hit rate metric
   - Cache size monitoring
   - Slow cache operation warnings
