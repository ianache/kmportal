<task type="auto">
  <name>Task 2: Implement Keycloak OAuth2 client and session middleware</name>
  <files>bff/src/config/index.ts, bff/src/auth/keycloak.ts, bff/src/middleware/session.ts, bff/src/types/express.d.ts</files>
  <action>
Implement the OAuth2/OIDC integration with Keycloak and Redis session management:

1. Create `bff/src/config/index.ts` - Centralized configuration:
   - Load environment variables with validation
   - Export typed config object
   - Fail fast if required vars missing (KEYCLOAK_URL, KEYCLOAK_CLIENT_SECRET, etc.)
   - Provide defaults for development (PORT=3000, NODE_ENV=development)

2. Create `bff/src/auth/keycloak.ts` - Keycloak OAuth2 client:
   - Use openid-client Issuer.discover() to fetch Keycloak OIDC metadata
   - Initialize Client with client_id, client_secret, redirect_uris
   - Implement exchangeCodeForTokens(code: string) → {access_token, refresh_token, id_token}
   - Implement refreshAccessToken(refreshToken: string) → new access_token
   - Export keycloakClient for use in routes
   - Handle PKCE if required (code_challenge, code_verifier)

3. Create `bff/src/middleware/session.ts` - Session management:
   - Initialize ioredis client with REDIS_URL
   - Configure express-session with connect-redis store
   - Session cookie settings (HttpOnly, Secure in prod, SameSite=lax)
   - Session TTL aligned with refresh token expiry (default 7 days)
   - Implement validateSession middleware that:
     * Checks for session cookie
     * Validates session exists in Redis
     * Returns 401 if session invalid/missing
     * Attaches user info (from session) to req.user
   - Implement requireAuth middleware for protected routes

4. Create `bff/src/types/express.d.ts` - TypeScript type extensions:
   - Extend Express.Request with user property
   - Define UserSession interface {id, email, roles, accessToken, refreshToken}
   - Ensure types are recognized by TypeScript compiler

Critical security requirements per BFF-03:
- Access tokens stored ONLY server-side in Redis session
- Frontend receives ONLY session cookie (HttpOnly, not accessible to JS)
- Refresh tokens used transparently when access tokens expire
