# Commit 487147e8

        **fix(api): use collection ID for ChromaDB operations and complete re-ingestion**

        This commit introduces a new `reingest.py` script to re-index 'done' documents into ChromaDB, using the document's domain ID as the collection name and generating embeddings for text chunks.

        ## Changed Files
        - `api/reingest.py`
- `api/src/adapters/vector_store/chroma_db.py`

        ## Entities
        - **api/reingest.py** (module): A new Python script responsible for re-indexing documents with 'done' status into ChromaDB, handling chunking, embedding generation, and collection creation based on domain ID.
- **reingest_documents** (function): The main asynchronous function in `reingest.py` that orchestrates the entire document re-ingestion process, including adapter initialization, database queries, text chunking, embedding generation, and ChromaDB collection management.
- **chunk_text** (function): A utility function that splits a given text string into smaller, potentially overlapping chunks, typically used to prepare text for embedding and vector storage.
- **ChromaDBAdapter** (class): An adapter class for interacting with the ChromaDB vector store, providing methods to manage collections and add embedded document chunks.
- **Document** (class): A SQLAlchemy model representing a document in the application's database, containing attributes like ID, title, domain ID, and processing status.
- **Embedding Adapter** (concept): An abstract component or interface (obtained via `get_embedding_adapter`) responsible for transforming text into numerical vector embeddings, specifically noted to be using an Ollama model.
- **ChromaDB Collection** (concept): A logical grouping of vector embeddings within the ChromaDB vector store, uniquely identified by a name, which in this commit is derived from a document's domain ID.
- **Document Re-ingestion Process** (concept): The workflow of extracting content from already processed documents, generating fresh embeddings for their chunks, and storing them in a vector database for retrieval.
- **Collection ID by Domain ID** (decision): The architectural decision to use the unique identifier of a document's domain (`domain_id`) as the name for its corresponding collection in ChromaDB, ensuring logical separation of document embeddings by domain.
- **SAMPLE_CONTENTS** (variable): A dictionary within `reingest.py` containing predefined textual content for various AI/ML concepts, used as example data for documents during the re-ingestion process.
