# Commit 5f960812

        **docs(05-bff-layer): create phase 5 plans for Node.js BFF**

        This commit creates the initial planning documents for Phase 5, the BFF layer, detailing three plans for Node.js BFF foundation, Core API proxying, and WebSocket events with Redis caching, and updates the project ROADMAP to reflect these new plans.

        ## Entities
        - **Phase 5: BFF layer** (concept): A Node.js Backend-for-Frontend (BFF) layer designed to proxy Keycloak authentication, expose REST endpoints to the frontend, push real-time ingestion events via WebSocket, and cache hot responses in Redis.
- **ROADMAP.md** (module): The primary document outlining the phased development plan for the Knowledge Management Center project.
- **05-01-PLAN.md** (module): The first detailed plan for Phase 5, focusing on establishing the BFF foundation using Express/TypeScript, implementing Keycloak OAuth2 proxy with HttpOnly session cookies, and setting up Redis-backed session management.
- **05-02-PLAN.md** (module): The second detailed plan for Phase 5, outlining the implementation of the Core API proxy and exposing REST endpoints from the BFF.
- **05-03-PLAN.md** (module): The third detailed plan for Phase 5, focusing on real-time WebSocket events for ingestion status and Redis caching for responses.
- **BFF Foundation + OAuth2 Proxy** (concept): The foundational stage of the BFF layer, encompassing project setup, Keycloak OAuth2 integration, and secure session management.
- **Express/TypeScript** (concept): The chosen technology stack for developing the BFF layer, combining the Express.js web framework with the TypeScript language for type safety and scalability.
- **Keycloak OAuth2** (concept): An open-standard protocol for authorization used to secure the BFF layer, handling user authentication and token exchange.
- **HttpOnly session cookies** (concept): A security mechanism for storing session identifiers in cookies that are inaccessible to client-side JavaScript, protecting against Cross-Site Scripting (XSS) attacks.
- **Redis sessions** (concept): The use of Redis as a scalable and persistent server-side store for managing user session data in the BFF.
